# Evry processing policy

These are EveryField safeguards, not Eve model/context limitations.

Each native turn allows up to 24 actual model calls, 2,000,000 cumulative reported input tokens and 64,000 output tokens. A single call requests no more than 8,000 output tokens or the remaining output allowance. Input usage is reported after a response, so the call crossing the input limit may finish; no subsequent paid call starts. Failed calls still consume a call reservation. Missing input accounting closes that turn's input allowance; missing output accounting charges the full output reservation. Neither grants unaccounted additional work.

The guard uses Eve's public durable `defineState` API. A `turn.started` hook initializes the allowance only when the native turn ID changes. Model middleware reserves before invoking the provider and records usage on generate completion or stream finish. A public `step.started` hook checks the same allowance without reserving again: Eve wraps errors from this boundary as recoverable turn failures, before context compaction. Dynamic tool resolvers are not used for enforcement because Eve logs and skips their errors. Park/replay of the same turn cannot replenish it. This also bounds provider retries and compaction using the same model wrapper.

An exhausted request ends with a specific processing-limit explanation and retains its transcript. The existing explicit Retry submits a new native turn and gets a fresh allowance. The guard does not silently loop or automatically retry, and does not execute any prepared mutation. Human plan confirmation remains separate.

A rare lifetime backstop remains at 40,000,000 input / 1,000,000 output tokens per saved conversation, using Eve's existing explicit Continue/Stop flow. Continue expands that session window but cannot replenish an exhausted turn. Normal conversation history no longer consumes the old 300,000/30,000 session window after a few requests.

Tradeoff: unusually broad investigations may stop and require a narrower request or explicit retry. These conservative ceilings are adjustable policy. They are not a monetary account budget; paid evaluations have a separate reservation-based dollar cap.

Proofs: `processing-budget.test.ts` exercises both provider methods, reservations, output caps and same-turn replay; `scripts/evry-eve-compiled-processing-budget.test.ts` uses the real compiled cookie-authenticated runtime and scripted provider to exhaust call/input allowances across durable steps, verify failure, retry and read-only replay. `scripts/evry-eve-compiled-limit.test.ts` covers the distinct lifetime backstop.

Eve 0.63 can make several summary calls inside one compaction operation. The tracked `patches/eve@0.63.0.patch` corrects its terminal-error path for conversation mode: compaction failures park the same saved conversation with `COMPACTION_FAILED`, retaining original history and requiring an explicit new user turn to retry. Task mode still throws; cancellation and steering take precedence. The application recognizes only the exact budget sentinel for processing-limit copy and keeps other provider errors generic. No summary or framework state is fabricated.

`scripts/evry-eve-compaction-recovery.test.ts` runs the installed patched Eve loop under plain Node. It exhausts the last available call during a multi-call compaction, separately injects a provider failure, verifies one failed turn with original history retained, and then completes an explicit Retry. It also verifies task-mode and cancellation behavior. Its scripted middleware isolates the framework boundary; the compiled processing test separately proves application middleware/state persistence. Reevaluate and remove this patch when an upstream Eve release supplies equivalent recovery semantics.

The combined durable proof is `scripts/evry-eve-compiled-compaction.test.ts`. First run `node --import tsx scripts/evry-eve-build-compaction-fixture.ts`; then set `EVRY_COMPACTION_FIXTURE_ENTRY` to the printed path and run that test. The builder copies the production agent under `.eve` and changes only Eve's public context-window/compaction configuration to 16K/90%. It does not edit production configuration, dependencies or `.output`. The fixture inherits the checkout's real dependencies through ordinary parent resolution; it never symlinks `node_modules`.

Four compiled cases cover provider failure and output-budget exhaustion inside multi-call compaction, each before and after explicit Retry. All use cookie authentication, real production model middleware/hooks, isolated Postgres and a scripted provider. Actual checkpoints retain an exhausted turn at 14 calls/118K input/64K output. Retry creates a new turn, sees the original failed prompt, and completes in two calls. Replacement-process read-only replay preserves the transcript with zero model calls, capability calls or outbound messages. No individual scripted input exceeds the fixture's 16K context size, and output stays within the app's 8K per-call limit.

The production Retry control uses `resumeWatching` in `evry-shell.tsx`, which sends `EVE_RETRY_MESSAGE` on the same saved session. There is no separate retry-turn API. `native-shell-proof.ts` mounts the real shell and verifies that handler for model errors, compaction provider errors and compaction budget errors, both immediately and after history replay. Double invocation produces one same-session POST, preserves the unsent draft, and never duplicates the original message. The compiled test sends that same message through native `session.send`; physical browser-click validation is separate.
