3 · The privacy spine + rubric delta

  • New table planter_checkins (church-scoped, one row per week — unique (church_id, week_start), upsert; four dimension values + optional note; migration via pnpm db:migrate).
  • Never in the fact snapshot. The check-in feeds no signals, no judge prompt, no insights, no oversight read — structurally unreachable by every pipeline that leaves the planter's own view.
  • Launch-green never washes planter-red: the private check-in strip (latest week's four dots + streak) renders beside the assessment on the planter's surface, so a green assessment is never shown without the care state next to it. Nudges ("pace has been strained three weeks running — who is caring for you?") are computed deterministically in UI code, not by the LLM.
  • Rubric v1 "what we cannot see" section: Plant Intelligence assesses launch health; planter sustainability is tracked privately and is never inferred. The judge is banned from claiming planter wellbeing, burnout, or capacity from any activity fact.

4 · Acceptance criteria (draft)

  1. AC-1 Schema. planter_checkins per §3; unique week upsert; migration.
  2. AC-2 Check-in UI. The weekly card (per D2): appears when the current week is unanswered; one tap per dimension (D1 shape); optional note; idempotent answer; cursor-pointer.
  3. AC-3 History. A private trend view (last ~12 weeks of dots) on the planter's surface; the launch-green-beside-care-state rule holds.
  4. AC-4 Privacy. A test proves check-in data is absent from the fact snapshot, judge prompt, and every oversight payload (sweep-style assertion, same pattern as the no-person-names sweep).
  5. AC-5 Rubric. The D0 draft carries the "what we cannot see" section and the activity-inference ban.
  6. AC-6 Works. Browser validation: answer a week, see the strip update; the following week the card returns.
  7. AC-7 Follow-up filed. Per D3: a discovery issue for coach/org sharing with consent design.
