1 · What the system knows today

Verified in code. The engine cannot currently apply Bryan's rule, because the one fact it needs does not exist.

Growth facts today

CoreGroupSignals exposes committedCount, growthDelta (trailing 28-day window vs the prior 28 — Bryan kept this), and growthWindowDays. There is no "days since the last new committed adult" — so "3 weeks flat" is something the judge eyeballs from a delta, and a +1 reset is unmeasurable.

Where thresholds are allowed to live

The trends layer (signals/trends.ts) is explicitly threshold-free by design — "NO THRESHOLD… nothing decides a number is low or bad" (verified banner). Thresholds belong in the fact snapshot + rubric text, same pattern as followUp.staleThresholdDays.

The v0 lines that change

"Flag stalled growth at: 3 weeks flat" — rubric-v0.md Lens 3

"Insight types: trajectory vs. launch; growth stalled N weeks" — rubric.ts CSF-3

I'd probably say "momentum has slowed" sooner, but I wouldn't confidently label growth "stalled" until roughly four weeks, especially because one vision-meeting cycle can radically change things. — Bryan, C22 (controlling)

2 · The design

One new fact makes the whole rule deterministic — the reset is not a special case, it is the fact's definition.

Addition Definition
daysSinceLastNewCommitment Whole days since the most recent person's first core_group commitment (signedDate). null at cold start. A new committed adult makes it 0 — the +1 reset is built into the fact, not a rule the judge applies.
slowedThresholdDays: 21 Constant fact, same pattern as staleThresholdDays — the judge cites it, never invents it.
stalledThresholdDays: 28 Same.

Rubric v1 Lens 3 delta (into the D0 draft)

  • "Flag stalled growth at: 3 weeks flat" becomes the two-level rule: "momentum has slowed" at ≥ 21 days since the last new committed adult; "stalled" only at ≥ 28 days.
  • The judge may not use the word stalled for any shorter streak — one vision-meeting cycle can change the picture.
  • Any new committed adult resets both clocks (inherent in the fact's definition; the rubric says so for the reader).
  • The 28-day comparison window (growthDelta) is untouched — Bryan kept it.

3 · Acceptance criteria (draft)

  1. AC-1 Fact. CoreGroupSignals gains daysSinceLastNewCommitment (null at cold start), slowedThresholdDays (21), stalledThresholdDays (28); snapshot assembler, fact-phrases.ts entries, and unit tests updated.
  2. AC-2 Reset semantics. A test proves a new first-commitment resets the streak to 0 and that a person's second commitment (e.g. launch team) does not.
  3. AC-3 Rubric. The D0 draft (rubric-v1.md + inactive RUBRIC_V1_BODY) carries the two-level Lens 3 rule; "3 weeks" is absent from v1; the comparison window stays 28 days.
  4. AC-4 Works. A fact-snapshot test proves the three facts reach the judge prompt. No UI, no browser gate.

4 · Boundaries

  • No schema change — commitments.signedDate already holds everything.
  • The vision-meeting cadence watch (21/28 days without a meeting) is a different rule — #486.
  • The 4+-members-disengaging percentage rewrite — #486.
  • "Net" is measured as new committed adults; commitment removal does not exist as a record, so a departure cannot un-reset the clock. If churn tracking ever lands, this fact gets revisited.
